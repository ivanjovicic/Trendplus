## What was done
- Root cause confirmed in code: `reloadNonce` (declared at `InventoryPage.tsx:436`) was set by `retryPageLoad()` and by the same-scope data-scope handler but never read; `inventoryQuery` did not depend on it and the hook's `refetch` was used only by `refreshOperations`. For non-custom presets `retryPageLoad()` re-set identical period values, so no request was sent. The loading/error/empty branches returned before the main layout, so the control bar was unmounted.
- `retryPageLoad()` now calls `useReliableAnalyticsQuery().refetch()` after the optional preset-range refresh (batched into one render, one request). It serves the error retry, the empty-state retry, the control-bar „Osveži“ action and the scheduler `onRefresh`.
- Removed the dead `reloadNonce` state; moved the data-scope handler below the query hook, replaced the same-scope nonce bump with `refetch()` and added `refetch` to its deps.
- Extracted the control-bar section into `renderInventoryControls(showDataSummary)`; the main layout renders stable child slots `[page header | null]`, `[controls]`, `[page body | loading/error/empty panel]` inside the existing `ErrorBoundary`, so the controls keep their DOM identity across error -> reload -> data and in empty states. While blocking, row/page/risk chips and the inline error line are suppressed (no fake zero counts).
- Controls are hidden only before the first primary load settles (`primaryLoadSettled`), preserving the original startup behaviour.
- Filtered empty state (`filtered_out`) gets actions „Poništi filtere“ (clears search, store, supplier; page 1) and „Pokušaj ponovo“; unfiltered empty (`no_data`) keeps the default actions.
- Added `src/pages/__tests__/InventoryPage.retryRecovery.spec.tsx` (6 cases): error retry sends exactly one new list request and recovers the table with controls visible; the same search input stays mounted from error through reload and recovery; filtered empty state keeps controls and retry sends exactly one request; „Poništi filtere“ clears the search and reloads unfiltered data; unfiltered empty offers no reset; control-bar „Osveži“ re-runs the request exactly once without dropping the table.
