## What was done

RQ144 was promoted as the smallest independently executable waiting prompt. Forecast, Shopify, vendor-comparison and live-worker work were explicitly excluded. The backend now distinguishes no revenue evidence from a measured zero share, keeps unavailable revenue shares nullable, rejects missing or non-finite denominator evidence as `insufficient_data`, and returns a non-success HTTP response instead of a zero-filled success payload when the health source fails. The API no longer reports snapshot generation as the last successful refresh. The frontend consumes the backend-owned `hasRevenueEvidence` state and does not infer a green health result from `totalRevenue` alone.
