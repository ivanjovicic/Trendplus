## What was done
- SalesLineFacts identity moved from (SaleId, ProductId) to the source receipt line (SaleId, SourceTableKey, SourceLineId).
- Design: prodaja_stavke lineage is unique only on (source_table_key, source_row_id), so both are stored. Lines without Access lineage (Trendplus POS) use namespace `trendplus.prodaja_stavke` with prodaja_stavke.id, so the id spaces cannot collide.
- New idempotent migration `20261010150000_KeySalesLineFactsBySourceLine`: nullable columns, non-unique (SaleId, ProductId) index, partial unique index WHERE SourceLineId IS NOT NULL. No backfill: the analytics database is separate from prodaja_stavke and identical doubled rows cannot be matched to source lines reliably.
- `20260909190000_AddSalesLineFactIdempotency` no longer raises on repeated lines and creates a non-unique index (production already applied it; EF does not re-run it).
- Writers updated: Access fast sync (delete-then-insert per sale, now carrying identity), admin analytics sync endpoint, startup backfill, outbox projection (one source line consumed per payload line, which also aligns per-line cost for repeated products).
