## Interpreted outcome

Preserve the complete available SKU, size and store identity when an Inventory alert opens the size-curve view, while keeping aggregate alerts explicit and preserving the existing size-curve error/empty/degraded states.

## Owner and scope

- Owner: Inventory alert component/callback, InventoryPage size-curve state, cached size-curve API/query/cache contract.
- In scope: `skuId`, `storeId` and nullable `sizeCode` from alert to frontend state, request, SQL filter and cache key; collision-safe alert navigation; focused contract tests.
- Out of scope: alert severity filtering and the RQ324 error/empty-state business semantics.

## What was done

- Extended the size-curve request and backend query with nullable `sizeCode` and an exact normalized SQL filter.
- Included `sizeCode` in the cached size-curve key so a size-specific request cannot reuse an aggregate response.
- Updated Inventory alert callback and page state to retain SKU/store/size identity; manual SKU entry resets alert-specific context.
- Preserved store-scoped aggregate behavior when an alert has no size code.
- Added UI, API, backend query and cache-key regressions.
- Synchronized a stale existing `SizeCurvePanel` test expectation with the already-established sanitized runtime error message; runtime error handling was not changed.
