# RQ319 - Unify Operacije Filter Apply Semantics

**Date**: 2026-10-08
**Status**: DONE

**Feature Family**: operations-filter-apply-consistency
**Priority**: P2

## Task Summary

Unify filter application behavior across all Operacije analytics screens (Shoe Type, Color, Pre/Post nivelacija). Implement consistent explicit "Primeni filtere" (Apply) pattern for date/period/store filter changes per ANALYTICS_DESIGN_SYSTEM.md §6.3 and owner-approved product decision.

### Problem Addressed

**Before RQ319**: 
- **Shoe Type**: Auto-applied preset, season, store changes immediately to activeFilters
- **Color**: Required explicit "Primeni filtere" (Apply) button
- **Pre/Post**: Required explicit "Primeni filtere" (Apply) button
- **Inconsistency**: Same Operacije menu group used conflicting mental models

**After RQ319**: 
- **All three screens**: Consistent explicit Apply for period/date ranges, store and multi-field filters
- **Draft state**: Changes edit draft state without triggering API calls
- **Apply button**: "Primeni filtere" commits draft to activeFilters and triggers refetch
- **Reset button**: Moved to secondary action; users must explicitly apply changes or reset

## Design System Compliance

**ANALYTICS_DESIGN_SYSTEM.md §6.3** (Approved 2026-10-04):
> Period, date ranges and multi-field filters: draft + **"Primeni" (Apply)**. While draft is not applied, control shows "Nije primenjeno" (Not applied) marker. Trust strip describes active (applied) period.
