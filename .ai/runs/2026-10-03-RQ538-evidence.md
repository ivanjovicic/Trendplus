## What was done
- Added optional store scope to the price-change request; null is chain-wide. Created audit events include supplier, origin and authenticated actor (or the explicit `admin-api-key` service actor), and admin access is checked server-side.
- Validated positive/changed prices and a configurable maximum markdown (`Pricing:Nivelacija:MaximumMarkdownPercent`, default 35%). Override is explicit, admin-gated and persisted in the event comment. The 35% default is an assumption aligned with the existing Pre-Nivelacija scenario cap and remains configurable.
- Replaced raw exception details with a safe Problem response and correlation ID.
- Added one shared event-store policy across vendor Pre/Post SQL, supplier split, color analytics and Pre-Nivelacija markdown lookup; store-scoped reads retain chain-wide events and exclude other stores.
- Updated `/api/nivelacije` to list imported and application-created event types, expose type/store columns, and apply Europe/Belgrade date filters with an inclusive selected end day implemented as an exclusive next-day boundary.
- Updated the history UI to label event origin/scope, use calendar-day filters, and explain that null store scope applies chain-wide.
